\section{RML Translation}%
\label{sec:rml_translation}
After establishing the formalism of our mapping algebra in
Section~\ref{sec:mapping_algebra}, we demonstrate its expressiveness by using
it to define the semantics of the RML mapping language, specifically version
1.1.2~\footnote{\url{https://rml.io/specs/rml/v/1.1.2/}}.
This section provides an algorithm that, given a valid arbitrary RML document,
generates an algebraic expression that captures the semantics of the mapping
process described in the input RML document.
We demonstrate that our mapping algebra is \textbf{at least as expressive as} RML, and 
provide a \textbf{well-defined formal semantics} for RML v1.1.2. 

\subsection{Translation Preliminaries}%
\label{sub:translation_preliminaries}
Before translating an RML document into our algebraic expression, a few
preparations are required: i)~normalization of the RML document,
ii)~identification of RDF sub-graph to translate algebraic expressions relevant
to a specific triples map, and iii)~definitions of extend functions for Extend
operator creation.



\subsubsection{RML normalization}%
\label{ssub:rml_normalization}
First, the input RML document is \emph{normalized} by following the steps outlined
in~\cite{Mariano2015SPARQL2SQL}, with adaptations specific to RML, as detailed
below:
\begin{enumerate}
    \item All \texttt{rr:class} definitions are replaced by predicate object maps,
	\item All shortcuts for constant-term maps have been expanded,
	\item All predicate-object maps with multiple predicate or object
	      maps are expanded into predicate-object maps with a single 
	      predicate map and a single object map,
	\item All referencing-object maps with a parent triples map without join
          conditions are replaced by an object map with the 
          subject IRI of the parent triples map as the reference value,
	\item All triples map with multiple predicate-object maps are
	      replaced by equivalent triples maps that each have one of
	      the predicate-object maps,
    \item All triples maps with multiple graph maps are replaced by a
          equivalent set of triples maps that each have one of the graph
          maps.
\end{enumerate}
After normalizations, all triples map in the normalized RML document have only
a single predicate-object map and if present, a single graph map. Moreover, all
term maps do not have shortcuts. 

\subsubsection{Triples Map-Specific RDF Graph}%
\label{ssub:tm_specific_rdf_graph}
Secondly, to support the translation process, we define two types of RDF
graphs within an RML document: i)~\textbf{$\triplesMapIRI$-specific triples map
graph}, and ii)~\textbf{$\triplesMapIRI$-specific parent triples map graph}. 
These graphs are used throughout the translation algorithm to translate the
relevant algebraic expressions from the triples in the RDF graph associated with
the chosen triples map~$\triplesMapIRI$.

\begin{definition}
	Let $\symRMLGraph$ be an RDF graph of an RML mapping document, and
	$\triplesMapIRI$ an IRI of a RML triples map.
	A \textbf{$\triplesMapIRI$-specific triples map graph
		$\triplesMapGraph{TM}{\triplesMapIRI} \subseteq \symRMLGraph$} is an RDF graph
	recursively defined as follows:
	\begin{enumerate}
		\item  $\triplesMapGraph{TM}{\triplesMapIRI}$ contains every triple
		      $(s,p,o) \in \symRMLGraph$ for which $s = \triplesMapIRI$
		\item if $(s,p,o) \in \triplesMapGraph{TM}{\triplesMapIRI}$, then
		      $\triplesMapGraph{TM}{\triplesMapIRI}$ also contains every triple
		      $(s',p',o') \in \symRMLGraph$ where $s' = o$.
	\end{enumerate}
\end{definition}

\begin{definition}
	Let $\symRMLGraph$ be an RDF graph of an RML mapping document, and
	$\triplesMapIRI$ an IRI of a RML triples map.
	A \textbf{$\triplesMapIRI$-specific parent triples map graph
		$\triplesMapGraph{PTM}{\triplesMapIRI} \in \symRMLGraph$} is an RDF graph
	defined as follows:
	\begin{enumerate}
		\item  $\triplesMapGraph{PTM}{\triplesMapIRI}$  contain every triple $(s,p,o) \in \symRMLGraph$
		      such that $p$ is the IRI \texttt{rr:parentTriplesMap} and $o = \triplesMapIRI$.
		\item If $(s,\texttt{rr:parentTriplesMap},o) \subseteq \triplesMapGraph{PTM}{\triplesMapIRI}$, then
		      $\triplesMapGraph{PTM}{\triplesMapIRI}$ also contains every triple $(s',p',o') \in \symRMLGraph$
		      such that $s'=s$ and  $p'$ is the IRI \texttt{rr:joinCondition}.
		\item If $(s,\texttt{rr:joinCondition},o) \in \triplesMapGraph{PTM}{\triplesMapIRI}$, then
		      $\triplesMapGraph{PTM}{\triplesMapIRI}$ also contains every triple $(s',p',o') \in \symRMLGraph$
		      such that $s' = o$ and  $p'$ is the IRI \texttt{rr:parent}.
	\end{enumerate}
\end{definition}


\subsubsection{Relevant Extension Functions}%
\label{ssub:built_in_extend_functions}
Lastly, we define the following extension functions~(as per Definition~\ref{def:ExtensionFunction})
to support the creation of Extend operators during the translation 
of RML descriptions into our formalism. 
\begin{itemize}
	\item
	$\toIRI$ is a unary extension function that converts string literals representing IRIs into these IRIs. Formally,  for every $v \in (\symTermUniverse \cup \error)$, we define:
\begin{equation*}
	\fctToIRI{v} =
	\begin{cases}
		\mathit{lex}
		& \text{if $v$ is a literal $\literalTuple$ such that $\lex$ is a valid IRI}
		\\[-2mm]
		& \text{and $\dt$ is the IRI \texttt{xsd:string},}
		\\
		\error
		& \text{else.}
	\end{cases}
\end{equation*}

	\item
	$\toBNode$ is a unary extension function for which we assume a function $\LTB: \symAllLiterals \rightarrow \symAllBNodes$ that is injective. Then, $\toBNode$ uses $\LTB$ to convert string literals into blank nodes. Formally, for every $v \in (\symTermUniverse \cup \error)$, we define:
\begin{equation*}
	\fctToBNode{v} =
	\begin{cases}
		\LTB(\lex)
		& \text{if $v$ is a literal $\literalTuple$ such that $\dt$ is the IRI \texttt{xsd:string},}
        \\ 
		\error
		& \text{else.}
	\end{cases}
\end{equation*}

	\item
	$\toLiteral$ is a binary extension function that converts string literals into literals with a datatype IRI that is given as the second argument. Formally, for every pair $(v, \dt)\in (\symTermUniverse \cup \error) \times (\symTermUniverse \cup \error)$, we define:
\begin{equation*}
    \fctToLiteral{v, \dt} = 
    \begin{cases}
        (\lex, \dt) &\text{if $v$ is a literal~$(\lex, \dt')$ such that $\dt'$ is the IRI \texttt{xsd:string}}, \\
        \error & \text{else.}
    \end{cases}
\end{equation*}

	\item
	$\concat$ is a binary extension function that concatenates two string literals. Formally, for every pair $(v_1, v_2) \in (\symTermUniverse \cup \error) \times (\symTermUniverse \cup \error)$, we define,
\begin{equation*}
    \fctConcat{v_1}{v_2} = 
    \begin{cases}
        (\lex_1 \circ \lex_2, \texttt{xsd:string})  &\text{if $v_1$ and $v_2$ are literals $(\lex_1,\dt_1)$ and}
		\\[-1mm]
        & \text{$(\lex_2,\dt_2)$, respectively, such that both}
		\\[-1mm]
        & \text{$\dt_1$ and $\dt_2$ are the IRI \texttt{xsd:string},}
        \\ 
        \error &\text{else,}
		\\
    \end{cases}
\end{equation*}
where $\lex_1 \circ \lex_2$ is the string obtained from concatenating the strings $\lex_1$ and $\lex_2$.
\end{itemize}


\subsection{Translation Algorithms}%
\label{sub:translation_algorithms}
We present the pseudocode of the algorithm to translate a normalized RML document 
to algebraic expressions in Algorithm~\ref{alg:rml2algebra}. 
Given an RDF graph of a \emph{normalized} RML document and for each triples map
in the RDF graph, the algorithm first generates a Source operator 
following Algorithm~\ref{alg:rml_source_op} where all the query expressions
detected, in the current triples map-specific RDF
graph~(Section~\ref{ssub:tm_specific_rdf_graph}), are extracted
(Algorithm~\ref{alg:query_extraction}) and composed to form the current 
algebraic expression being translated~$\omega'$. 
Subsequently, the relevant Extend operators are extracted, according to 
Algorithm~\ref{alg:rml_termmap_extend_expr}, for both the subject and the 
predicate term maps (line 6-11) where the Extend operators generate the 
subject and predicate terms while binding them to the attributes $\subjAttr$ and $\predAttr$ 
respectively. 

To extract the Extend operators from the object maps, we need to also
determine if it is a referencing-object
map~\footnote{\url{https://rml.io/specs/rml/\#logical-join}}. 
If the object map is a referencing-object map (line 14-28), the algorithm first
extracts the Source operator for the parent triples map (line 15-18) and stores
it into a temporary algebraic expression~$\omega_{ptm}$, then retrieves the
join attributes (line 20-24) for the Equi-join operator (line 25), and finally,
the algebraic expression~$\omega'$ is updated with the Equi-join operator (line
26-28).
Otherwise, the object map is treated the same as the subject and the predicate map 
where an Extend operator is extracted directly (line 30-31). 
The Extend operator generated for the object map binds the value returned by 
evaluating the extend expression to the attribute $\objAttr$. 

To get determine the RDF graph of the triples to be generated, 
an Extend operator, to generate the graph IRI, is generated from the graph map 
that exists in the triples map (line 33-36). 
If there is no graph map in the triples map, a default graph IRI is generated 
with the value \texttt{rr:defaultGraph} (line 37-38). 
The attribute $\graphAttr$ contains the graph IRI to be generated by the 
Extend operator. 

Finally, a Projection operator is applied to only have the attributes 
$\subjAttr, \predAttr, \objAttr$, and $\graphAttr$, in the mapping 
relations resulting from the root operator of 
the algebraic expression (line 40-41). 
To capture all the mappings described in the RML document, a Union operator 
is applied between the accumulated expression~$\omega$ and the current 
algebraic expression~$\omega'$ (line 42). 
At the end of this algorithm, we have an algebraic expression $\omega$ that 
captures the full semantics of the mapping process described in a given 
normalized RML document. 


\begin{algorithm}[h!tbp]
	\caption{RML translation to algebraic mapping expressions Part 1}
	\label{alg:rml2algebra}
	\begin{algorithmic}[1]
		\Require $\symRMLGraph$ an RDF graph of a \textbf{normalized} RML document, 
        \Statex \qquad $\LTB$ an injective function mapping literals to blank nodes, 
        \Ensure A mapping definition
        \State $\omega \gets$ initially empty algebraic expression
		\For{$(\triplesMapIRI, \texttt{rdf:type}, \texttt{rr:TriplesMap}) \in \symRMLGraph$}
	    	\State  $(\queryExpr_{root},\symAttrQueryMap) \gets$ \textbf{TranslateSourceOperator}($\symRMLGraph, \triplesMapIRI$) \Comment{Algorithm~\ref{alg:rml_source_op}}
            \State   $src \gets \textrm{initSrc}(o')$ for $(\triplesMapIRI,\texttt{rr:logicalSource},o') \in \triplesMapGraph{TM}{\triplesMapIRI}$ \Comment Definition~\ref{def:init_data_source}
	    	\State   $\omega' \gets \sourceOp{src}{\queryExpr_{root}}{\symAttrQueryMap}$

            \State $tm_{sub} \gets o$, where triple $(s,\texttt{rr:subjectMap},o) \in \triplesMapGraph{TM}{\triplesMapIRI}$ such that $s = \triplesMapIRI$
            \State $\extExpr \gets $\textbf{ExtractExtendExpr}($\symRMLGraph, \LTB, \symAttrQueryMap, tm_{sub}$) \Comment Algorithm~\ref{alg:rml_termmap_extend_expr}
            \State $\omega' \gets \extOpAttr{\attr_{s}}(\omega')$
            \State $tm_{pred} \gets o$, where triple $(s,\texttt{rr:predicateMap},o) \in \triplesMapGraph{TM}{\triplesMapIRI}$ such that $s = \triplesMapIRI$
            \State $\extExpr \gets $\textbf{ExtractExtendExpr}($\symRMLGraph, \LTB, \symAttrQueryMap, tm_{pred}$)
            \State $\omega' \gets \extOpAttr{\attr_{p}}(\omega')$
		    \State\dots  \Comment Continued in Algorithm~\ref{alg:rml2algebra_part2}
		    \algstore{state:full_translation}
	\end{algorithmic}
\end{algorithm}

\begin{algorithm}[h!tbp]
	\caption{RML translation to algebraic mapping expressions Part 2}
	\label{alg:rml2algebra_part2}
	\begin{algorithmic}[1]
		\algrestore{state:full_translation}
            \State $tm_{obj} \gets o$ where triple $(s,\texttt{rr:objectMap},o) \in \triplesMapGraph{TM}{\triplesMapIRI}$ such that $s = \triplesMapIRI$ 
            \If{$(tm_{obj},\texttt{rr:parentTriplesMap},o') \in \triplesMapGraph{TM}{\triplesMapIRI}$}
		        \State $s_{ptm} \gets o'$
		        \State  $(\queryExpr_{root},\symAttrQueryMap) \gets $ \textbf{TranslateSourceOperator}($\symRMLGraph, s_{ptm}$) \Comment{Algorithm~\ref{alg:rml_source_op}}
                \State   $source_{ptm} \gets \fctInitSrc{o''}$ with $(s'',\texttt{rr:logicalSource},o'') \in \triplesMapGraph{TM}{s_{ptm}}$ 
		        \State  $\omega_{ptm} \gets \sourceOp{source_{ptm}}{\queryExpr_{root}}{\symAttrQueryMap}$
                \State $\symJoinAttrPairs \gets \emptyset$
                \For{$(tm_{obj},\texttt{rr:joinCondition},o') \in \triplesMapGraph{TM}{\triplesMapIRI}$}
                    \State  $a \gets \symAttrQueryMap^{-1}(o'') $ for $o''$ in triple $(o',\texttt{rr:child},o'') \in \triplesMapGraph{TM}{\triplesMapIRI}$
                    \State  $a_{ptm} \gets \symAttrQueryMap^{-1}(o'')$ for $o''$ in triple $(o',\texttt{rr:parent},o'') \in \triplesMapGraph{TM}{\triplesMapIRI}$
		            \State  $\symJoinAttrPairs \gets \symJoinAttrPairs \cup \{ (a, a_{ptm}) \}$
                \EndFor
		        \State  $\omega' \gets \fctEquiJoinOp{\omega'}{\omega_{ptm}}$
                \State $tm_{sptm} \gets  o''$ with $(s'',\texttt{rr:subjectMap},o'') \in \triplesMapGraph{TM}{s_{ptm}}$ 
                \State $\extExpr \gets $\textbf{ExtractExtendExpr}($\symRMLGraph, \LTB, \symAttrQueryMap, tm_{sptm}$)
                \State  $\omega' \gets \extOpAttr{a_{o}}(\omega')$
            \Else
                \State $\extExpr \gets $\textbf{ExtractExtendExpr}($\symRMLGraph, \LTB, \symAttrQueryMap, tm_{obj}$)
                \State  $\omega' \gets \extOpAttr{a_{o}}(\omega')$
		    \EndIf
            \If{$(s,\texttt{rr:graphMap},tm_{graph}) \in \triplesMapGraph{TM}{\triplesMapIRI}$} 
                \State $\extExpr \gets $\textbf{ExtractExtendExpr}($\symRMLGraph, \LTB, \symAttrQueryMap, tm_{graph}$) 
                \State $\omega' \gets \extOpAttr{\attr_{g}}(\omega')$
            \Else
                \State $\extExpr \gets \texttt{rr:defaultGraph}$
                \State $\omega' \gets \extOpAttr{\attr_{g}}(\omega')$
            \EndIf
            \State $\symProjSet \gets \{\attr_{s},\attr_{p},\attr_{o},\attr_{g},\}$
            \State $\omega' \gets \fctProjectOp{\symProjSet}{\omega'}$
            \State $\omega \gets  \fctUnion{\omega'}{\omega}$
		\EndFor
	\end{algorithmic}
\end{algorithm}


\begin{algorithm}[htbp]
	\caption{QueryInTriplesMap: Extract query expressions from RML triples maps}
	\label{alg:query_extraction}
	\begin{algorithmic}[1]
		\Require  $\symRMLGraph$ an RDF graph of RML document,
		\Statex  \qquad $\triplesMapIRI$ the subject IRI of a triples map
		\Ensure  A set of query expressions

		\State $\symDataAcc \gets \emptyset$ \Comment Initially empty set of query expressions
		\For{$(s,p ,o) \in \triplesMapGraph{TM}{\triplesMapIRI}$ s.t.\ $p$ is the IRI \texttt{rml:reference} and $o$ is a literal $(\lex,\dt) \in \symAllLiterals$}
		    \State $\symDataAcc \gets \symDataAcc \cup \{ \lex \}$
		\EndFor
		\For{$(s,p ,o) \in \triplesMapGraph{TM}{\triplesMapIRI}$ such that $p$ is the IRI \texttt{rr:template} and  $o$ is a literal $(\lex,\dt) \in \symAllLiterals$}
		    \State $\symDataAcc' \gets$ set of all substrings in $\lex$ that are enclosed by \{ and \}
		    \State $\symDataAcc \gets \symDataAcc \cup \symDataAcc'$
		\EndFor
		\State $T_\textrm{child} \gets \{ (s,p,o) \in \triplesMapGraph{TM}{\triplesMapIRI} \, | \, p \text{ is the IRI } \texttt{rr:child} \}$
		\State $T_\textrm{parent} \gets \{(s,p,o) \in \triplesMapGraph{PTM}{\triplesMapIRI} \, | \, p \text{ is the IRI } \texttt{rr:parent} \}$
		\For{$(s,p,o) \in (T_\textrm{child} \cup T_\textrm{parent})$ such that $o$ is a literal $(\lex,\dt) \in \symAllLiterals$ }
		    \State $\symDataAcc \gets \symDataAcc \cup \{ \lex \}$
		\EndFor
		\State \Return $\symDataAcc$
	\end{algorithmic}
\end{algorithm}


\begin{algorithm}[htbp]
	\caption{ExtractExtendExpr: Extend expression translation from an RML term map}
	\label{alg:rml_termmap_extend_expr}
	\begin{algorithmic}[1]
		\Require 
            $\symRMLGraph$ an RDF graph of RML document,
            \Statex \qquad $\LTB$ an injective function mapping literals to blank nodes, 
            \Statex \qquad $\symAttrQueryMap$ a partial function mapping attributes to query expression,
            \Statex \qquad $tm$ subject IRI of the RML term map to translate the extend operator for
		\Ensure An extend expression
        \State $\extExpr \gets $ initially empty extend expression

        \If{$\triplesMapGraph{TM}{tm}$ contains a triple $(tm, \texttt{rr:reference}, o)$ such that $o$ is a literal $\literalTuple$ }
    		\State $\extExpr \gets a$, where $a$ is the attribute in $\fctDom{\symAttrQueryMap}$ such that $\symAttrQueryMap(a) = \lex$
		\ElsIf{$\triplesMapGraph{TM}{tm}$ contains a triple $(tm, \texttt{rr:constant}, o)$}
    		\State $\extExpr \gets o$
		\ElsIf{$\triplesMapGraph{TM}{tm}$ contains a triple $(tm, \texttt{rr:template}, o)$ such that $o$ is a literal}
            \State  $\extExpr \gets $ \textbf{Template}($o, \symAttrQueryMap$)  \Comment Algorithm~\ref{alg:template_function}
		\EndIf
\medskip
        \If{$\triplesMapGraph{TM}{tm}$ contains the triple $(tm,\texttt{rr:termType}, \texttt{rr:BlankNode})$}
            \State \Return $\fctToBNode{\extExpr}$
        \ElsIf{$\triplesMapGraph{TM}{tm}$ contains the triple $(tm,\texttt{rr:termType}, \texttt{rr:IRI})$}
            \State \Return $\fctToIRI{\extExpr}$
        \ElsIf{$\triplesMapGraph{TM}{tm}$ contains a triple $(tm, \texttt{rr:datatype}, o)$ such that $o \in \symAllIRIs$}
            \State \Return $\fctToLiteral{\extExpr, o}$
        \Else 
            \State \Return $\fctToLiteral{\extExpr, \texttt{xsd:string}}$
		\EndIf
	\end{algorithmic}
\end{algorithm}

\begin{definition}
    \label{def:tempSubStrs}
    Let $v = (\lex, \dt)$ an input literal string such that $\dt$ is \texttt{xsd:string}.  
    For ease of reading, we call a substring of $\lex$ an \textbf{enclosed query substring} 
    if it is the substring starting and ending with the curly braces \{ and \} respectively, as defined in R2RML~\citeneeded, 
    otherwise it is called as \textbf{normal substring}.
    $\tempSubStrs$ is a unary function which splits $\lex$ into a sequence~$\substrSeq$
    of substrings of $\lex$ that contains alternating normal substrings and
    enclosed query substrings in two pass as follows: 

    \begin{enumerate}
        \item  An intermediate sequence~$\substrSeq'$ of substrings is generated that 
            contains substrings that are \textbf{normal} or \textbf{enclosed query}  
            substrings in the order that these substrings appear in $\lex$ from 
            left to right. 
        \item $\substrSeq'$ is further processed as follows to produce $\substrSeq$: 
            \begin{enumerate}
                \item If $\substrSeq'$ is empty, a new empty substring is inserted into $\substrSeq'$.
                \item For every two enclosed query substrings that occur directly after one another in $\substrSeq'$, a new empty substring is inserted into $\substrSeq'$ in between these two enclosed query substrings.
                \item If the first element in $\substrSeq'$ is an enclosed query substring, 
                    a new empty substring is inserted into $\substrSeq'$ as the new first substring.
                \item If the last element in $\substrSeq'$ is an enclosed query substring, 
                    a new empty substring is appended to the end of $\substrSeq'$.
            \end{enumerate}
    \end{enumerate}
\end{definition}

After the aforementioned processing, $\substrSeq$ is an
alternating sequence of normal substrings and enclosed query substrings
with the enclosed query substrings at every second position, and $\substrSeq$ 
is not empty and has an odd number of elements.


\begin{algorithm}[htbp]
	\caption{Template: An algorithm which extracts an extend expression for 
        resolving the template string of the input literal node.}
	\label{alg:template_function}
	\begin{algorithmic}[1]
        \Require $(\lex, \dt)$ a literal, 
        \Statex \qquad $\symAttrQueryMap$ a mapping of attributes in $\symAttrUniverse$ to query expressions in $\symDataAcc$
		\Ensure An extend expression
        \State $\substrSeq \gets \fctTempSubStrs{\lex}$ \Comment Definition~\ref{def:tempSubStrs}
        \State $\extExpr \gets (s_1, \texttt{xsd:string})$, where $s_1$ is the first element in $\substrSeq$
        \If{$|\substrSeq| > 1$}
            \For {$i \in 2,\dots,|\substrSeq|$}
                \State $s_i \gets $
                    the $i$-th element in $\substrSeq$
                \If{$s_i$ is a string that starts with ``\{" and ends with ``\}"}
                    \State $\queryExpr \gets $ substring of $s_i$ without the enclosing ``\{" and ``\}"
                    \State $\extExpr \gets \fctConcat{\extExpr}{\symAttrQueryMap^{-1}(\queryExpr)}$ 
                \Else
                    \State $\extExpr \gets \fctConcat{\extExpr}{(s_i, \texttt{xsd:string})}$   
                \EndIf
		    \EndFor
        \EndIf
		\State \Return $\extExpr$
	\end{algorithmic}
\end{algorithm}


\begin{algorithm}[htbp]
	\caption{TranslateSourceOperator: Source operator translation for a given triples map IRI $\triplesMapIRI$}
	\label{alg:rml_source_op}
	\begin{algorithmic}[1]
		\Require $\symRMLGraph$ an RDF graph of RML document,
		\Statex \qquad $\triplesMapIRI$ subject IRI of a triples map 
		\Ensure A tuple containing a root query expression and a partial function $\symAttrUniverse  \rightarrow  \symDataAcc$
		\State $ls_{iri} \gets o$ for a triple $(s,p,o) \in \symRMLGraph$ where $s = \triplesMapIRI$  and $p= \texttt{rml:logicalSource}$
		\State $\queryExpr_{root} \gets o$ for a triple $(s,p,o) \in \symRMLGraph$ where $s = ls_{iri}$  and $p=  \texttt{rml:iterator }$
		\State $\symDataAcc \gets$ \textbf{QueryInTriplesMap}($\triplesMapIRI, \symRMLGraph$) \Comment{Algorithm~\ref{alg:query_extraction}}
		\State $\symAttrQueryMap \gets$ initially empty function from attributes to query expressions in $\symDataAcc$
		\For{$\queryExpr \in \symDataAcc$}
		\State $\attr \gets$ a fresh attribute from $\symAttrUniverse \setminus \{ \attr_\textrm{s}, \attr_\textrm{p}, \attr_\textrm{o}, \attr_\textrm{g} \}$ that has not been used before in this translation process
		\State $\symAttrQueryMap \gets \symAttrQueryMap \cup \{ a \rightarrow \queryExpr \}$
		\EndFor
		\State \Return  $(\queryExpr_{root}, \symAttrQueryMap)$
	\end{algorithmic}
\end{algorithm}

\begin{definition}
    \label{def:init_data_source}
    Let $ls_{iri}$ be an IRI of an RML logical source. 
    We denote $\fctInitSrc{ls_{iri}}$ as a \textbf{data source}, $\dataSourceTuple$, derived 
    from the configurations of the given logical source~$ls_{iri}$.
\end{definition}
For example, given an RDF graph~$\symRMLGraph$ of an RML document in Listing~\ref{lst:rml_document}, 
and a triple $(s, \texttt{rml:logicalSource}, ls_{iri}) \in \symRMLGraph$, 
$\fctInitSrc{ls_{iri}}$ returns a data source tuple, $\dataSourceTuple$, such 
that $\symDataset$ is a CSV dataset from the file ``sport.csv" and 
$\sourceType =  \sourceTypeTuple$ such that  $\symSetDataset$ is a set of  
CSV datasets, $\symDataAcc$ a set of all possible query expressions applicable to the 
given CSV dataset, such as column names.
$\eval$ is a function that returns a row of CSV data object per
iteration, and $\cbeval$ is a function that returns the data object for the
given CSV column name.
